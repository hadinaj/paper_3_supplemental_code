# Conceptual Model Representation Notes

This document records representation decisions used in the conceptual data model artifact. It explains how candidate entities, reference entities, selected attributes, candidate identifiers and linking fields, grouped attribute structures, and relationship-evidence categories are represented across the conceptual data model artifact. The notes preserve traceability between the table-level conceptual entity mapping, source-to-concept attribute dictionary, schema representations, and the final model artifact.

| Model representation element | Element type | Meaning in model | Related mapping or source | Representation decision | Notes |
|---|---|---|---|---|---|
| Semantic orientation representation | conceptual model representation | Groups candidate conceptual entities into broad conceptual areas and provides short human-readable descriptions | conceptual_entity_mapping.md | Entity labels use terminology from the table-level conceptual entity mapping; short descriptions summarize the intended meaning for stakeholder orientation | This representation does not show identifiers, source columns, relationship evidence, or cardinality. |
| Candidate entity box | entity notation | Represents a candidate conceptual entity derived from one or more inspected source structures | conceptual_entity_mapping.md | Shown as an entity in the conceptual data model artifact | Candidate entities are reviewable and not stakeholder-validated concepts. |
| Reference entity | entity notation | Represents a code-definition, item-definition, provider, or other reference structure used to interpret source records | conceptual_entity_mapping.md | Retained as a reference entity | Included to preserve interpretation of coded or identifier-based fields. |
| Candidate identifier/linking field | attribute notation | Represents fields used to identify source records or connect source structures | source_to_concept_attribute_dictionary.csv | Shown explicitly where needed for traceability | Candidate identifiers are not necessarily formally declared primary keys. |
| Grouped attribute structure | abstraction notation | Represents multiple related source fields as a higher-level conceptual attribute group | source_to_concept_attribute_dictionary.csv | Grouped to avoid flattening all source columns in the main artifact | Used for structures such as laboratory result value, reference range, medication timing, or microbiology result components. |
| Solid relationship line | relationship notation | Complete conservative inferred relationship | relationship assessment output | Shown as empirically supported inferred link | Used when candidate link had zero null source-link rows and zero unmatched non-null rows. |
| Non-solid or visually distinguished relationship line | relationship notation | Relationship requiring contextual interpretation | relationship assessment output | Shown as reviewable or contextual link | Used for links affected by null source-link patterns or partial/context-dependent match results. |
